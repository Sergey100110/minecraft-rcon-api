# minecraft-rcon-api
RCON клиент для Minecraft с HTTP сервером.
# Возможности:
- **IP-фильтрация** - фильтрация запросов по белому/чёрному списку IP адресов.
- **Авторизация** - возможность включить авторизацию по токенам доступа.
- **Настройка прав доступа** - возможность ограничить доступ отдельных токенов к определённым возможностям RCON запросов.
- **Форматы ответов** - поддерживаются JSON и HTML.
- **Лёгкость настройки расширения** - легко настроить для управления миром в Minecraft.

### Если сервер установлен самостоятельно, тогда нужно:
#### 1) Открыть файл server.properties.
#### 2) Изменить 3 настройки:
 - enable-rcon -> true (Включение RCON).
 - rcon.port -> 25575 (Порт, на котором будет работать RCON). **Не должен пересекаться с портом, который установлен в query.port и server-port!** В качестве примера установлен на 25575.
 - rcon.password -> ВАШ_ПАРОЛЬ (Пароль для подключения к RCON).
#### 3) Перезапустить сервер, чтобы применить изменения.

# Запуск сервера:
## Перейдите в директорию с программой.
> cd ПУТЬ_ДО_ПАПКИ\src
## Запустите HTTP сервер. Для примера запустим сервер на порту 8000.
> php -S 0.0.0.0:8000
#### Возможно у вас появится окно, что защитник Windows заблокировал действия PHP. Разрешите доступ, иначе сервер работать не будет.
#### Теперь сервер будет принимать входящие соединения со всех адресов на порту 8000.
# Чтобы подключиться к серверу, введите в браузере "http://IP_АДРЕС_ВАШЕГО_ПК:8000". Он выдаст ошибку 404, чтобы её не было, нужно добавить "/main.php". Тогда получится адрес "http://IP_АДРЕС_ВАШЕГО_ПК:8000/main.php". Сервер должен вернуть другую ошибку, так как он не настроен. Если соединение не устанавливается - проверьте порт сервера, брандмауэр, а также состояние командной строки, в которой вы запустили сервер. Её нельзя закрывать, иначе сервер остановится.
# Настройка сервера:
## Конфигурация сервера хранится по пути "ПУТЬ_ДО_ПАПКИ\src\system\config.php".
## Параметры конфигурации:
### ban_mode - режим фильтрации IP адресов. Возможные значения:
> 0 - фильтрация отключена.
> 1 - отклонить запросы от всех IP адресов, входящих в список.
> 2 - отклонить запросы от всех IP адресов, не входящих в список.
### tokens_enable - требовать авторизацию по токенам. Возможные значения:
> 0 - разрешить анонимные подключения.
> 1 - запретить подключения без авторизации.
### ips - список IP адресов, которым разрешён или запрещён доступ. Режим фильтрации зависит от параметра ban_mode.
### tokens - список токенов доступа. Нужны для авторизации, если tokens_enable равен 1.
### rcon_host - адрес для подключения к RCON серверу.
### rcon_port - порт для подключения к RCON серверу.
### rcon_password - пароль для подключения к RCON серверу.
### rcon_connection_timeout - таймаут для подключения к RCON серверу в секундах.
# Настройка прав доступа по токенам.
## Начиная с версии 1.1.0 была добавлена возможность ограничения доступа пользователей к отдельным объектам по переменной device.
> [!NOTE]
> **Контроль доступа работает только если настройка tokens_enable установлена на 1. Если настройка установлена на 0, то конфигурация контроля доступа игнорируется.**

## Настройки хранятся в файле по пути "ПУТЬ_ДО_ПАПКИ\src\security\securityconfig.php".
## Настройки:
### allow_if_not_defined - определяет действие по умолчанию, если пользователь не определён в списке security_tokens_filter_mode. Если равен true - действие будет разрешено, если равен false - запрос будет отклонён.
### security_tokens_by_objects - список объектов, доступ к которым будет иметь токен по политике в security_tokens_filter_mode. Должен содержать JSON. Пример:
#### Один токен qwerty:
> {"qwerty":"1"}

#### Несколько токенов (qwerty и test):
> {"qwerty":"1","test":"2"}

### security_tokens_filter_mode - политика доступа токена к объектам из списка security_tokens_filter_mode. Возможные значения:
> blacklist - блокировать доступ к объектам, прописанным в списке.
> whitelist - блокировать доступ к объектам, не прописанным в списке.
> ignore - игнорировать пользователя, разрешая все действия.
#### Сделаем доступ для токена qwerty ко всем объектам:
> {"qwerty":"ignore"}

#### Сделаем доступ токену qwerty по чёрному списку, а токену test - по белому.
> {"qwerty":"blacklist","test":"whitelist"}

> [!CAUTION]
> **1) Если вы установили режим фильтра на blacklist или whitelist, то в поле security_tokens_by_objects должны быть указаны объекты! Если объекты не указаны - доступ будет разрешён независимо от режима фильтра или настройки allow_if_not_defined.**

> [!CAUTION]
> **2) На текущий момент возможна следующая проблема: если например у вас есть устройство 1,2 и 12, но вы хотите ограничить доступ только к устройству 12, то вы потеряете доступ ко всем 3 устройствам! Это связано с особенностями работы алгоритма фильтра. Я постараюсь исправить это в будущих обновлениях. Временное решение:**
> а) Называйте устройства так, чтобы их названия не пересекались. Например, если у вас есть устройство in_door, и вы хотите ограничить доступ к другому объекту с именем door - переименуйте его, например, в other_door.
> б) Старайтесь называть устройства без спецсимволов, кроме нижнего подчёркивания, чтобы не нарушить совместимость в будущих версиях.
> в) Называйте устройства каким-то набором случайных букв и цифр + понятным вам названием.

# API и запросы на HTTP сервер.
## Параметры запроса:
### token - токен для авторизации. При ошибке вернёт ошибку 403.
### device - "номер" "устройства". Является первой служебной переменной. Является обязательной, при её отсутствии сервер вернёт ошибку 400.
### state - состояние, в которое должно перейти "устройство". Является второй служебной переменной. Является обязательной, при её отсутствии сервер вернёт ошибку 400.
### json - тип ответа. Если true - сервер ответит JSON-ом, если false или не указан - HTML. JSON включает в себя:
#### status - успех запроса. true - успех, false - провал.
#### code -  код ответа. 200 - успех, все остальные - ошибка.
#### error_message - наименование ошибки. OK - успешно, все остальные - ошибка.
#### message - Текстовое описание ошибки от сервера.
# Настройка своих триггеров для управления миром Minecraft:
## Функционал нужно прописывать в файле handle.php, который находится в одной папке с config.php.
## Примеры:
### Сделаем управление временем в мире:
```php
<?php
function handle($_rcon){
$_device = $_GET['device'];
$_state = $_GET['state'];
if($_device == "world_time"){
$_rcon->sendCommand('/time set ' . $_state);
}
}
?>
```
### Выгоним игрока с сервера:
```php
<?php
function handle($_rcon){
$_device = $_GET['device'];
$_state = $_GET['state'];
if($_device == "player"){
if($_state == "1"){
$_rcon->sendCommand('/kick PlayerNik');
}
}
}
?>
```
### ~Скрестим мух с котлетами~ Совместим два последних примера в один:
```php
<?php
function handle($_rcon){
$_device = $_GET['device'];
$_state = $_GET['state'];
if($_device == "player"){
if($_state == "1"){
$_rcon->sendCommand('/kick PlayerNik');
}
}
else if($_device == "world_time"){
$_rcon->sendCommand('/time set ' . $_state);
}
}
?>
```
> [!NOTE]
> Вам не нужно вручную подключаться к серверу RCON - программа сделает это автоматически, а после выполнения отключится от него.

> [!TIP]
> Если программа не сможет подключиться к RCON серверу, она отправит HTTP ответ с ошибкой 500.

# Работа с ответами HTTP сервера.
## Пример запроса:
### http://ВАШ_IP:8000/main.php?json=true&token=ВАШ_ТОКЕН&device=123&state=1
## Пример ответа:
### Успех:
> {"status":"true","code":"200","error_message":"OK","message":"Request sended."}
### Ошибка подключения:
> {"status":"false","code":"500","error_message":"Internal Server Error","message":"RCON connection failed."}
### Некорректный запрос:
> {"status":"false","code":"400","error_message":"Bad Request","message":"Error: 'state' is not declared."}
### Недостаток прав (начиная с версии 1.1.0):
> {"status":"false","code":"403","error_message":"Forbidden","message":"Not enough rights."}
